# 비교 사이트 수집 명세 · 검수 부담 최적화

## 목표

웹북의 각 자산을 실제 제품에 적용할 때 참고할 수 있도록, 디자인 완성도가 높은 비교 사이트를 수집한다. 사이트 이름보다 캡처한 화면의 디자인 품질과 해당 자산에 주는 참고 가치로 판단한다. Opus 5.5가 빠르게 비교·판정할 수 있도록 제출물은 짧고 시각적으로 정리한다.

## 수집 범위

- 시험 자산은 기존 4판의 10개 항목(`about-001`부터 `table-001`)을 그대로 사용한다.
- 자산마다 서로 다른 사이트를 최대 2곳까지 선정한다. 전체 목표는 최대 20곳이다.
- 기준을 충족하는 후보가 부족하면 수를 채우지 말고 찾은 곳만 제출한다.
- 기존 비교 결과와 같은 사이트는 제외한다. 주소가 다르더라도 동일 브랜드·같은 제품의 화면이면 중복으로 본다.
- 한국 회사·브랜드·스튜디오의 한국어 사이트를 우선한다. 해당 자산에서 수준 높은 한국 사례를 확인하지 못했을 때만 해외 수상·선정 사이트를 최대 1곳 대체 후보로 넣고 `해외 대체`라고 표시한다.

## 선정 기준

화면을 직접 열어 다음을 확인한다.

1. 첫눈에 드러나는 구체적인 디자인 선택이 있다. 예: 사진과 제목의 규모 관계, 타이포그래피 위계, 정렬과 여백, 정보 밀도, 색의 비중, 상호작용의 표현.
2. 해당 자산과 화면의 목적이 맞는다. 기능 화면을 찾는 항목은 실제 그 기능이 보이는 화면을 사용하며, 회사 첫 화면으로 대신하지 않는다.
3. 비교할 만한 한 가지 강점이 캡처에 실제로 보인다. `세련됨`, `깔끔함` 같은 모호한 평가만으로 선정하지 않는다.
4. 수상·선정 이력이나 디자인 근거를 적을 때는 확인 가능한 공식 수상 페이지, 선정 페이지, 또는 해당 화면을 구체적으로 다룬 기사·공식 글의 주소를 붙인다. 근거를 찾지 못하면 수상 사실을 추정하지 말고 `수상 근거 미확인`으로 적는다.
5. 템플릿 모음, 포털 첫 화면, 공공기관, 지원·약관·로그인 등 운영용 보조 페이지, 빽빽한 상품 목록은 디자인 비교에 실질적인 가치가 없는 경우 제외한다. 사이트 규모나 유명세만으로 합격시키지 않는다.

## 캡처 기준

- 기본은 사이트당 데스크톱 화면 1장, 1920×1080으로 제한한다. 모바일 캡처와 전체 페이지 캡처는 하지 않는다.
- 정적인 디자인 자산은 그 디자인을 가장 잘 보여주는 첫 화면 또는 해당 구역을 캡처한다.
- 동작이 핵심인 자산(FAQ, 로그인, 폼, 갤러리, 가격 전환, 정렬 표 등)은 실제로 조작한 뒤 **그 자산의 디자인과 상태가 가장 잘 드러나는 대표 장면 1장**을 찍는다. 동작 전 화면보다 답변 펼침, 검증 결과, 선택된 요금제, 정렬 결과처럼 목적과 시각 표현을 함께 보여주는 상태를 우선한다.
- 전·후 두 장은 변화 자체가 디자인 판단에 꼭 필요해 한 장으로 전달할 수 없을 때만 허용한다. 이 경우에도 해당 자산에서 최대 두 사이트 중 한 곳에만 적용하고, 두 장이 필요한 이유를 목록에 한 문장으로 적는다.
- 캡처를 늘리기 위한 추가 화면·기기 크기·반복 상태는 만들지 않는다. 동작을 직접 확인할 수 없으면 장면을 꾸며내거나 추측하지 말고 `동작 확인 불가`라고 기록한다.
- 로그인·결제·문의 전송 등 실제 계정이나 외부 전송이 필요한 조작은 하지 않는다. 공개된 상태만 확인하고, 안전한 데모 입력으로 완료 상태를 재현할 수 있을 때만 사용한다.
- 쿠키 안내와 가림 팝업은 닫고, 화면 로딩이 끝난 뒤 촬영한다. 접근 차단·오류·빈 화면이면 다른 후보를 찾고, 이를 정상 화면인 것처럼 제출하지 않는다.

## 제출물

저장 위치: `E:\Project\output\research\comparison-sites-4pan-revised-<날짜시각>\`

- 사이트별 PNG와 `목록.md`를 저장한다. 파일 이름은 `<자산번호>-<자산id>-<a|b>-<사이트영문명>-<1920>.png`로 한다. 전·후가 꼭 필요한 경우 파일명 끝에 `-before`와 `-after`를 붙인다.
- `목록.md`에는 자산 ID, 사이트명, 실제 화면 주소, 한국/해외 대체 구분, 디자인에서 비교할 구체적 포인트 한 문장, 동작 확인 결과, 수상·선정 근거 주소(확인된 경우), 캡처 파일명을 기록한다.
- 포인트는 관찰 가능한 근거로 쓴다. 예: `첫 화면에서 제목이 화면 폭의 절반을 차지하고 건축 사진이 오른쪽 전체 높이를 채움.` 근거 없는 점수·전문가 평가·수상 주장은 쓰지 않는다.
- 검수용 `사진목록.html`은 자산별 사진을 나란히 볼 수 있게 만든다. 전·후 캡처가 있으면 같은 사이트 아래 묶어 순서대로 보여준다.
- 새 폴더만 사용하고 기존 결과를 덮어쓰지 않는다. 파일이름·주소·이미지 크기와 실제 캡처가 일치하는지 확인한다.

## 완료 판정

- 실제 브라우저에서 연 화면만 제출하며, 캡처와 목록의 사이트·상태가 서로 일치한다.
- 최대 20개 사이트, 기본 최대 20장이다. 꼭 필요한 전·후 비교가 있을 때만 추가되며, 자산당 한 곳에서만 허용한다.
- 기준 미달 후보를 채워 넣지 않는다. 부족한 자산은 이유와 함께 `후보 없음`으로 남긴다.
- 완료 보고에는 저장 폴더, 실제 사이트 수와 이미지 수, 미충족 자산, 직접 확인하지 못한 동작만 간단히 적는다. 조사나 캡처를 하지 않았다면 완료로 보고하지 않는다.
