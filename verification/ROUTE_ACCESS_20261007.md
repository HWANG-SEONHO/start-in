# Render 직접 접속·새로고침 검증 — 2026-10-07

## 실제 수정

start-in-web 정적 사이트 대시보드의 Redirects/Rewrites에서 기존 API 규칙 다음에 React SPA fallback을 추가했다. URL을 바꾸는 Redirect가 아니라 Rewrite다.

1. /api/* → https://start-in-api.onrender.com/api/* (Rewrite, 기존 규칙 유지)
2. /* → /index.html (Rewrite, 신규)

앱 코드·모션·서버 요금제는 변경하지 않았다. 이 설정은 Render 대시보드에 저장되며 Git pull만으로 다른 서비스에 자동 적용되지는 않는다. 새 정적 사이트를 만들 때도 위 순서로 설정해야 한다. 실제 존재하는 정적 파일은 Render에서 파일로 제공한다.

## 배포 사이트에서 직접 확인

- /main: 메인 데이터 로딩, 413개 부산 공고, 새로고침 정상.
- /intro: 직접 접속·새로고침, 실제 3D 로봇 ready 확인.
- /: 인트로 표시, 준비 후 서비스 바로가기 → /main 및 공고 로딩 확인.
- /jobs: 10개 공고 로딩·새로고침. 다음 페이지 → page=2 및 새로고침 후 다른 10개 공고 확인.
- /jobs/957: 직업교육 강사 상세 데이터·새로고침 확인. 실제 목록에 있는 공고로 검증.
- /companies: 150개 기업 표시·새로고침 확인.
- /companies/103: 데모기업 098 · 리드랩 상세 및 채용공고 표시·새로고침 확인.
- /login, /register: 로그인·가입 폼 렌더링 및 새로고침 정상. 폼 제출하지 않음.
- /my: 비로그인 상태에서 /login으로 이동 확인. 로그인 후 MY 내용은 검증하지 않음.
- /coming-soon?feature=채용 Q&A: 인코딩된 주소로 제목 유지·새로고침 확인.
- /route-check-not-found: CDN의 빈 404 대신 React의 '페이지를 찾을 수 없습니다.' 안내 표시 확인.
- 부산+서울 선택: 10개 카드, 조건 URL 반영, 새로고침 후 두 지역 결과 유지.
- 프론트엔드 검색: 현재 main 화면에서 검색어와 조건을 유지하며 결과 갱신. 일치하는 공고 제목 확인. 전체 공고 링크 이동 후 새로고침하면 6개 결과 유지.
- /api/health: 200 JSON. 3D JS 파일: 200 application/javascript. React catch-all이 API·정적 파일을 가로채지 않음.
- 마지막 목록 페이지에서 브라우저 error 로그 0건.

## 검증 한계

로그인·회원가입 화면이 열린다는 사실만으로 인증 기능 전체 정상이라고 하지 않는다. 계정 생성·실제 로그인·저장·지원·이력서 업로드는 배포 데이터를 변경하지 않기 위해 실행하지 않았다. 1,000개 모든 공고와 150개 모든 기업의 상세를 개별 방문한 것도 아니다. 대표 상세로 라우팅·데이터 흐름을 확인했다.

초기 검수 시 /main 검색이 /jobs로 자동 이동한다고 잘못 가정해 테스트 대기 조건이 실패했다. 실제 UI는 main 안에서 결과를 갱신하는 구조여서 대상을 바로잡고 다시 확인했다. 인트로 바로가기는 초기 로딩 화면이 덮고 있는 동안의 동작까지 완료 판정하지 않았고, 준비 이후 실제 메인 진입을 확인했다.
